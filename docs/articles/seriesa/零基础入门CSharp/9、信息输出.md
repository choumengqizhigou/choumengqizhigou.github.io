贴下上节代码：

``` Csharp
class Program
{
	static void Main()
	{
		int num1 = 100;
		int num2 = 200;
		int sum = 0;

		sum = num1 + num2;
	}
}
```

目前再来看这个代码，应该不至于那么可怕了吧！

上节内容我们说了，最后的运算结果 `300` 会存到变量 `sum` 中去。

可等你真的运行程序的时候，你会发现程序依然是一闪而过。

这其实不违背最开始介绍的逻辑，代码从 `Main方法` 的 `{` 开始， 到 `Main方法` 的 `}` 结束。

在整个 `Main方法` 的 `{}` 范围内，一共写了四句代码。

程序运行的时候，执行玩这四句代码，然后直接结束也非常符合逻辑。

不过这里你说的很漂亮，逻辑很清晰，程序的逻辑也符合了，但是并不代表我的逻辑符合了呀！

我还想看看最终的数据展示呢！


## Console

程序的逻辑非常清晰，只要把你要做的事情通过代码都描述清楚了，就能得到自己想要的结果。

比如目前四句代码，只是定义变量，再经过加法运算，最后把结果存入变量 `sum` 中。

并没有要求进行 `sum` 结果的输出，所以需要加入新的代码来输出 `sum` 中的值。

只不过输出信息到屏幕还是比较麻烦的，这时候需要借助一个叫做 **标准库** 的东西。

其实就是 `C#` 官方给我们写好的一些代码方法。


### Console.WriteLine()

现在我们要调用的是 `Console` 类型下面的 `WriteLine` 方法，用来把 `sum` 输出到屏幕上。

想要访问到这个类型，需要告知我们它到底是在哪个命名空间下。

因为之前我们有描述过 `C#` 的代码结构大概是：`命名空间` -> `类型` -> `方法` 。

所以很显然，需要明确告知 `Console` 这个类型的 `命名空间` 是什么才能进行访问。

`Console` 的命名空间是 `System` ，我们输出的代码就会变成：

``` Csharp
System.Console.WriteLine(sum);
```

现在我们需要输出 `sum` ，直接把 `sum` 放在示例代码的位置即可。

> 调用方法，需要方法名加上()，最后分号结尾。
> 这里也可以看一下，我们是直接使用的 `sum` ，并且不是在 `=` 左边，所以其实就是在取 `sum` 的值，也就是 `300` 。

那么完整的代码就变成了：

``` Csharp
class Program
{
	static void Main()
	{
		int num1 = 100;
		int num2 = 200;
		int sum = 0;

		sum = num1 + num2;

		System.Console.WriteLine(sum);
	}
}
```

现在当你再次运行程序，可能还会跟之前一样，程序启动之后直接就关闭了。

这还是一样的问题，代码虽然从四句变成了五句，可是核心逻辑没变。

程序依然是快速的执行了五句代码。

那是否有一种方式，能够让程序在某一行代码中暂停呢？或者让代码一直在执行，来达到暂停的目的呢？


### Console.ReadKey()

想让程序不那么快结束，我们有很多种方式。

这里介绍一种同样是 `Console` 类型下的 `ReadKey()` 方法。

这个方法的意思就是：**获取用户按下一个字符或者功能键** 。

我们可以理解为 **任意键** ，当然键盘上没有 `任意键` 这个具体的按键，而是任何一个键盘上的按键。

调用这个方法跟上面类似：

``` Csharp
System.Console.ReadKey();
```

只不过这个方法不需要我们像上面一样，传入一个参数 `sum` 。

> 方法的定义、传参，介绍方法的时候会专门来说。

那么所有的代码就变成了：

``` Csharp
class Program
{
	static void Main()
	{
		int num1 = 100;
		int num2 = 200;
		int sum = 0;

		sum = num1 + num2;

		System.Console.WriteLine(sum);
        System.Console.ReadKey();
	}
}
```

此时再去运行程序，你会发现，程序真的暂停住了，并且还显示了 `sum` 的值 `300` 。

![sum值输出截图](images/48676792-c1b6-46f6-88f3-c3a26c08be2a.png)

这时候你随便按下一个按键，比如 `Enter` 回车键，程序就会顺利结束。

虽然功能有点简陋，但是毫不夸张的说。

**你用程序写了自己的第一个计算器。**

只不过目前这个计算器的功能稍微有点简陋。

只有加法，并且每次计算都需要修改代码中的数字后，重新编译运行程序才能看到结果。

后续其实可以让用户自己去输入数字，这样就能跟真正的计算器一样了。


## using

在代码的书写过程中，能够减少一部分命名空间的引入。

比如在使用 `Console` 类型的时候，每次都书写 `System` 这个命名空间，其实是比较麻烦的。

可以考虑统一拿到代码头部，通过 `using` 的方式来引入。

那么代码就会变成：

``` Csharp
using System;

class Program
{
	static void Main()
	{
		int num1 = 100;
		int num2 = 200;
		int sum = 0;

		sum = num1 + num2;

		Console.WriteLine(sum);
		Console.ReadKey();
	}
}
```

直接写上 `Console` 这个类型就行了。

那么你可能会问：**既然命名空间能通过 `using` 为啥不直接把 `Console` 也挪动上去呢** ？

很遗憾的告诉你，在 `C#` 中这是不被允许的。

但是如果你真的想 `using` 类型。

那么其实有另外一种 `using` 的用法。

### 类型别名

前面说到，可以在头部使用 `using` ，把当前代码中需要的命名空间进行一个统一引用。

其实 `using` 还有一个其它的用法，就是给已有的类型取一个自己的名字。

写起来也是非常简单，现在不是需要使用 `Console` 这个类型么。

我想给 `Console` 取一个别的名称，方便以后形成个人或者公司的特定规范。

格式就是：

``` Csharp
using 自定义名称 = 命名空间.类型;
```

那就可以直接这么写：

``` Csharp
using MyConsole = System.Console;

class Program
{
	static void Main()
	{
		int num1 = 100;
		int num2 = 200;
		int sum = 0;

		sum = num1 + num2;

		MyConsole.WriteLine(sum);
		MyConsole.ReadKey();
	}
}

```

这么写的话， `Console` 类型就可以叫 `MyConsole` 了，使用的时候也可以直接用 `MyConsole.WriteLine(sum);` 。

而且因为我们暂时只用到了 `System` 命名空间下的 `Console` 类，可以看到连 `using System;` 也一并去掉了。

> 也可以做命名空间的别名，比如不想叫 `System` ，那可以直接写 `using MySystem = System;` 。

其实 `using` 还可以用来自动释放资源，这个我们在后续再来说明。
