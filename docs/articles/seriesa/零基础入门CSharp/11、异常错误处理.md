程序的错误是不能容忍的，因为一旦发生错误，程序就会立即关闭。

对用户的使用也是及其不友好的。

所以对可能发生错误的代码，需要提前对错误进行预判，进行错误的捕获，这样在出现错误的时候，能够让程序按照预定的轨道继续运行。


## try-catch

捕获程序的错误非常简单，只要用 `try{} catch{}` 套一下就行了。

在上一节中，我们最容易的出现错误的代码就是：

``` Csharp
...
int num1 = int.Parse(content1);
...
```

在把用户输入的值，由 `string类型` 转换成 `int类型` 的时候，由于无法控制用户的输入，用户也可能因为无意识的情况输入一些无法转换的值，比如 `abc123` 。

这句代码的错误，咱们已经可以预判到了，自然就需要进行错误的提前预防。

做法也是很简单，代码如下：

``` Csharp
...
try
{
	//int num1 = 100;
	int num1 = int.Parse(content1);
}
catch 
{
	MyConsole.WriteLine("输入的并不是一个数字！");
}
...
```

`try{}` 的大括号范围内放上 **可能出错的代码** ， `catch{}` 的大括号范围内放上 **出错后需要执行的代码** 。

有几个点需要列出来说一下：

* `try{}` 的大括号同样是表示范围的，所以里面可以包含多句代码，只不过目前暂时就这一句转换类型的代码；
* 如果 `try{}` 的代码，并没有报错，那 `catch{}`  中的代码是不会执行的。

再就是 `try{}` 是可以写多句代码的，目前只有一句代码，真报错了，你也很清楚就是xxx错误。

可是如果要是有多句代码，我怎么知道是哪句代码报错，又是什么报错信息呢？

这里其实还有一个参数咱们没交代， `catch{}` 是可以书写一个报错参数的，我们可以直接使用这个参数来得到报错的更多信息。

书写逻辑就是 `catch(Exception ex) {}` ，这样如果要是报错走了 catch{} 的范围，我们就可以使用这个参数 `ex` ，来获得更多的报错信息。

这里先过一遍，让你有个概念，后续内容会演示具体使用！


### 再述变量作用域

**真要按照上方代码操作，你会发现代码直接就会报错。**

![num1trycatch报错截图](images/c1debc6c-33fc-47f8-bc92-22cc42e728f2.png)

下方 `sum = num1 + num2;` 提示了错误： **当前上下文中不存在名称 "num1"** 。

这其实没什么难理解的，就是变量作用域的问题，我们是在 `Main{}` 大括号下方的 `try{}` 大括号范围内定义 `num1` 的。

所以也只能在 `try{}` 大括号范围内和它的子范围内才能使用 `num1` 这个局部变量。

解决这个问题也很简单，我们可以在 `try{}` 的大括号外部先定义 `num1` ，这样两个地方就都能访问 `num1` 了。

流程上也没什么问题，代码自上而下依次执行，先走 `try{}` 里面的代码，再走下方剩余的代码。

改造后的代码就是：

``` Csharp
...
// 先定义num1，初始值为0
int num1 = 0;

try
{
	// int num1 = 100;
	num1 = int.Parse(content1);
}
catch
{
	MyConsole.WriteLine("输入的并不是一个数字！");
}
...
```

先把 `num1` 定义好了，然后再在 `try{}`  中使用，重新给 `num1` 赋值。

> 变量不要重复定义， `num1` 在 `Main{}` 范围内定义之后，它的代码下方以及子范围内都不能再次定义同名变量 `num1` 。

完成了可能出现的代码错误捕获，下面就来试试效果吧。

你输入一个正确的数值，代码跟之前是一样的效果：

![trycatch正常演示截图](images/1ccb480f-1c2f-4f6e-bb93-ebef39140cc2.png)

要是输入一个无法转换的，程序也不会报错，而是按照预定的 `catch{}` 路线执行：

![catch触发演示截图](images/d61fa3d9-dd1d-423a-be67-b354f9c2a0cc.png)

这里输入的值是 `abc123` ，显然是不能进行正常数字转换的，直接就提示了 `catch{}` 中的输出代码： **输入的并不是一个数字！**

> 不知道你是否有疑问，要是 `catch{}` 的范围流程中也出现可能错误的代码呢？那是否会意味着 `catch{}` 里面也要再放一个 `try{} catch{}` ，这样岂不是会变成无限套娃？
> 哈哈哈，很庆幸你能有这个想法，这样的做法也是完全支持的，不过一般我们不会这么干，其实还会有一种兜底的 **全局错误捕获** ，就相当于把整个 `Main()` 方法中的代码都套在一个 `try{} catch{}` 中。


### 改造num2

目前我们只是对 `num1` 的转换赋值进行了改造，同理也可以进行 `num2` 的改造。

改造代码还是一样的，先在外部定义 `num2` ，然后再去 `try{}` 中进行转换赋值。

改造代码如下：

``` Csharp
...
MyConsole.WriteLine("请输入要计算的二个数字：");

string content2 = MyConsoleReadLine();

//int num2 = 200;
int num2 = 0;

try
{
	num2 = int.Parse(content2);
}
catch
{
	MyConsole.WriteLine("输入的并不是一个数字！");
}
...
```

经过这样的错误捕获，咱们程序的健壮性已经提升一大步了。

![两个catch都触发演示截图](images/f6dcaa83-9075-49ed-a7b3-6729cf8e8f7b.png)

现在随便用户怎么输入，都不太可能会报错了，只是可能因为 `num1 num2` 都得不到正确的可计算的值，所以最终输出的是 `0 + 0` 的结果。

**能否让用户停留输入呢，直到输入正确的数字，再进行下一个数字的输入。**

## try-catch-finally

这是一个 `try{} catch{} finally{}` 的完整结构，这里做个简单的说明，不改动代码了。

代码的流程是：正常走 `try{}` ，异常走 `catch{}` ，不论正常还是异常都会走 `finally{}` 。

换成代码形式就是：

``` Csharp
...
try
{
	// 正常都走这里
}
catch
{
	// 报错就走这里
}
finally
{
    // 不管上面怎么走，我这里都要走
}
...
```

这种结构虽然是最完整的，但不是所有的地方都需要。

比如我们这里在 `try{} catch{}` 后续的代码，不论正确与否都是会走的，就跟写在 `finally{}` 中一样，所以无需单独写一个 `finally{}` 。

另外就是有没有 `finally{}` 不是一条绝对的道路，只是说适合与不适合，并不是说没有这一步一定不能怎么样。

其实有些代码确实也更适合写进 `finally{}` ，具体等你遇到的时候，自然会感受到这种境况，这里就不做过多的示例了。

> 写代码的逻辑就是这样的，设计语言的人为了满足更多的使用情况，会给你设计很多种语法，只不过日常满足开发需求的就那十几个，或者说高频用法的就那几个。
> 这件事情其实很像汉字有成千上万个，但是你掌握几百个就能直接创作了，直白的文字依然能创作出动人的故事。

> 说了这么多，希望你有一个概念，开始的时候不要追求所谓的精通、系统性学习，这都是伪命题，更多的是追求个别方向的深入学习，然后日常不断的巩固、练习、补充。经验也好，能力也好，其实不是技术本身的价值，而是个人经年累月的感悟和积累。
