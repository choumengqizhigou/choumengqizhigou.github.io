现在你已经通过 `VS` 创建了自己的第一个 `C#` 代码项目，也能做到实时修改，实时运行。

``` Csharp
Console.WriteLine("这是我的第一句代码");
 ↓
Console.WriteLine("Hello World");
```

照着上面代码这么修改，重新点击 `运行` ，黑框中的文字也会从 `这是我的第一句代码` 变更为 `Hello World`。

现在我们要回归之前演示代码编译的部分，将 `VS` 处理的这部分流程和之前的部分稍微对应一下。

比如之前咱们 `手动编译` 代码的时候，还生成过一个 `.exe` 结尾的可执行程序，这些内容都去哪里了？


## VS 2022项目流程说明

当你点击 `运行` 的时候，其实 `VS` 帮你 **编译了代码** ，并且生成了 **可执行应用程序** ，并且启动这个 **程序** 。

所以你点击 `运行` 的时候，看到的就是这个程序的运行效果。

**那这个程序的路径在哪里呢？**

![bin\Debug目录展示](images/e8468ea9-752e-43b7-a4c5-29b421976fb5.png)

如果你没更改过相关的路径设置的话，默认编译后的文件就在我们项目的 `bin\Debug` 文件夹目录下。

![直接启动FirstCode.exe截图](images/3dac9adb-ba92-4b0d-97f2-c6f87fe24ec5.png)

双击这个 `FirstCode.exe` 也一样能打开我们的程序。

**如果手动双击打开程序不关闭，在 `VS` 中是可能会无法点击运行。因为在 `VS` 中点击运行的时候，要是需要重新编译你的代码，那么就会覆盖这个 `FirstCode.exe` 。代码没修改过，可能就不需要重新编译， `VS` 会直接启动之前编译过的`FirstCode.exe` 。**

![obj\Debug目录展示](images/b99db102-d767-4a8c-bd58-fa159595c860.png)

上图也可以看出来，`VS` 其实是先将代码编译到 `obj\Debug` 目录，然后再复制到 `bin\Debug` 目录下的。

所以你自己双击打开 `FirstCode.exe` ，就会导致这个程序被占用，无法进行覆盖替换。

![编译提示文件占用](images/fa1db294-3866-4d1b-9ccf-d41a42e91143.png)

去到 `obj\Debug` 这个目录，确实能看到刚编译好的 `FirstCode.exe` ，双击也是可以正常打开运行的。


## Debug和Release

`Debug` 和 `Release` 是 `VS` 为我们默认提供的两组 **编译选项** ，选择不同的选项，到时候会组合不同的编译参数给到 `csc.exe` 。

它们各自都可以配置一组 `编译参数` ，一般情况下我们 **开发程序阶段** 选用 `Debug` ，**发布程序阶段** 选用 `Release` 。

### 快捷选择编译选项

![编译选项调整](images/856a62f5-c373-4e4c-9769-44d05d175d21.png)

初始阶段，咱们直接用 `VS` 默认的配置选项就行了。

直接在 `启动` 旁边就可以快捷的设置 `Debug` 、 `Release` 这两个编译选项。

你开发程序就默认选择 `Debug` ，想把程序发给别人就选上 `Release` 。

> 值得注意的是，选择不同的编译选项，最终的编译文件会在不同的文件夹中。之前默认演示的是在 `bin\Debug` 目录下的 `FirstCode.exe` 。如果改为 `Release` ，那么最终文件就会是 `bin\Release` 目录下的 `FirstCode.exe` 。


### 调整编译选项参数

如果真的想看看如何去调整 `Debug/Release` 两个选项的具体编译参数。

![项目右键属性](images/297d0268-7a21-434f-a80b-d6ed1ca8a552.png)

可以直接 `解决方案资源管理器` -> `右键 FirstCode项目` -> `点击属性` 。

这时候左侧就会弹出当前项目的属性配置窗口，我们选择到 `生成` 。

![Debug配置参数截图](images/0c4f6a9d-0f23-42f1-8096-3dd866254040.png)

**配置选择为 `Debug` 时：**

1. 勾选 `定义 DEBUG 常数` 
2. 取消勾选 `优化编码`
3. 输出路径 `bin\Debug\`

![Release配置参数截图](images/08866794-aca0-4487-a18c-391677be0f05.png)

**配置选择为 `Release` 时：**

1. 取消勾选 `定义 DEBUG 常数` 
2. 勾选 `优化编码`
3. 输出路径 `bin\Release\`

`VS` 会根据你的选择，到时候组合这些参数，生成一个编译命令，交给编译器来执行。

我们也可以自由调整这些参数，比如你觉得 `Debug` 选项的 `bin\Debug` 这个目录不好，那可以改成一个其它的目录。

> 关于一个项目相关的配置参数，`VS` 都会帮我们记录下来。最终都会保存在我们的项目文件中，就是我们当前项目目录的 `.csproj` 文件中，可以用记事本打开。

> ![FirstCode.csproj内容截图](images/77cca4c8-64c0-482c-9d6e-4998f81e5553.png)

> 这里我用记事本打开了 `FirstCode.csproj` ，可以看到内容是以 `XML` 格式的文本来存储的，这里单独标了一个 `OutputPath` 这个参数，主要还是其它参数太过生疏。所以你在 `VS` 中通过图形界面操作修改，和直接修改这里的文本，都是一样的意思。


## 代码错误演示

代码的结构和规范非常重要，如果你有尝试过随便加点什么内容，当你点击 `运行` 的时候， `VS` 会直接提示你一些错误，告诉你这些代码并不能成功的编译。

![随意输入代码内容666](images/091af990-0cd3-4abb-9161-248a44bf2913.png)

打开代码文件 `Program.cs` ，在这个位置加了一段代码 `666` ，这时候会发现代码的附近会有 **红色的波浪线** ，此时要是点击 `运行` ，就会弹出一个错误窗口，提示 **发生生成错误，是否继续并运行上次的成功生成？** 。

如果你点击 `是` ，就会忽略这次编译，启动原先已经成功编译过的那个 `FirstCode.exe` 。

如果你点击 `否` ，那么你可以在下方的 **错误列表** 中，看到 `VS` 给你提示的错误信息。

![错误列表界面截图](images/c1ec717a-7f5c-48c6-bb23-7ca6f3a04927.png)

告诉我们 **应该要输入分号** 。

直接双击这个错误信息，光标就会定位到出错的地方。

> 如果没有错误列表窗口，希望你还记得 **视图** 菜单中，可以找到这些窗口。比如 `视图` -> `错误列表` 。

> ![菜单操作错误列表](images/15f249a8-97f2-4746-b264-9ab1ad0445eb.png)
