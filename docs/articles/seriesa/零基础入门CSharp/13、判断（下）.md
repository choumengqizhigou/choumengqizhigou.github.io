做完了一个 **加法** ，剩下的就容易多了。

用户输入的运算符被记录在 `operatorSymbol` 变量中，第一个 `加法判断` 是用它和 `+` 比较。

如果相等就执行 `加法计算` ，如果不相等就继续执行后面的代码。

所以现在当我们输入一个 `-` 减法运算符号的时候，那第一个 `加法判断` 肯定是不满足的，咱们可以在 `加法判断` 的后面依次补充 `减法判断` 、 `除法判断` `、乘法判断` 。

开始操作吧！


## 完善加减乘除

按照上述的逻辑，可以补充以下代码：

``` Csharp
...
//加法判断
bool isPlus = operatorSymbol == "+";  // false;  //true;
if (isPlus)
{
	MyConsole.WriteLine("需要进行加法运算");
	int sum = 0;

	sum = num1 + num2;

	MyConsole.WriteLine(sum);
}

//减法判断
bool isMinus = operatorSymbol == "-";
if (isMinus)
{
	MyConsole.WriteLine("需要进行减法运算");
	int difference = 0;

	difference = num1 - num2;

	MyConsole.WriteLine(difference);
}

//乘法判断
bool isMultiply = operatorSymbol == "*";
if (isMultiply)
{
	MyConsole.WriteLine("需要进行乘法运算");
	int product = 0;

	product = num1 * num2;

	MyConsole.WriteLine(product);
}

//除法判断
bool isDivide = operatorSymbol == "/";
if (isDivide)
{
	MyConsole.WriteLine("需要进行除法运算");
	int quotient = 0;

	quotient = num1 / num2;

	MyConsole.WriteLine(quotient);
}

MyConsole.WriteLine("计算已经完成");
...
```

补充完了之后，忽然发现自己有点厉害了，竟然可以写这么多代码了。

正常测试 `+ - * /` 也都能响应正确的判断，进行计算的结果输出。

![加减乘除运算结果合并](images/a6630e11-b47b-44dd-a149-e28950c6e3ab.png)

可当你回头仔细欣赏这段代码的时候，其实很容易就能感知到这块代码的问题。

这里对同一个变量，采用了 `4` 次判断，可是它只能同时满足一种情况，也就是说，第一个判断要是成立了，就代表运算符是 `+` 号运算符，后面再去判断的意义就不大了。

那是否有一种方式，可以改善这种情况呢？先判断 `+` 号运算符，如果满足了，后面就不走了，如果不满足，再去判断下一个，以此类推...

## if-else

`if-else` 算是一个判断的完整结构，但并不是必须结构，就跟前面介绍 `try-catch` 中的 `finally` 一样，即使不用它，我们也可以通过其它方式来变相的实现软件的功能效果。

`if-else` 的语义也很简单，直白点就是： **如果满足就执行 `if` 的范围代码，否则就执行 `else` 的范围代码** 。

所以我们这里的代码完全可以改造成：

``` Csharp
...
//加法判断
bool isPlus = operatorSymbol == "+";  // false;  //true;
if (isPlus)
{
	MyConsole.WriteLine("需要进行加法运算");
	int sum = 0;

	sum = num1 + num2;

	MyConsole.WriteLine(sum);
}
else
{
	//减法判断
	bool isMinus = operatorSymbol == "-";
	if (isMinus)
	{
		MyConsole.WriteLine("需要进行减法运算");
		int difference = 0;

		difference = num1 - num2;

		MyConsole.WriteLine(difference);
	}
	else
	{
		//乘法判断
		bool isMultiply = operatorSymbol == "*";
		if (isMultiply)
		{
			MyConsole.WriteLine("需要进行乘法运算");
			int product = 0;

			product = num1 * num2;

			MyConsole.WriteLine(product);
		}
		else
		{

			//除法判断
			bool isDivide = operatorSymbol == "/";
			if (isDivide)
			{
				MyConsole.WriteLine("需要进行除法运算");
				int quotient = 0;

				quotient = num1 / num2;

				MyConsole.WriteLine(quotient);
			}
		}
	}
}

MyConsole.WriteLine("计算已经完成");
...
```

经过这样的改造，代码嵌套稍微多了一点，但是并没有发生特别难以理解的事情。

并且这么写的话，好处就是咱们的判断更有 **针对性** 了。

这所有的` if-else` 变成了一个整体，虽然代码嵌套了好几级，但只要其中有一个判断条件满足了，执行了相应范围的代码之后，就会直接跳出整个 `if-else` 的判断逻辑了。

直接梳理代码可以看到，第一个 `if` 先是判断了 `+` 号运算符，此时咱们可以先在内心进行代码模拟，无外乎就两种情况：

**1. 用户输入 `+` 号运算符**

表示满足 `if(+)` 的判断，则直接执行 `if(+){}` 范围内的 **加法** 相关代码，然后跳出整个 `if-else` 的代码范围。

**2. 用户输入非 `+` 号运算符**

很显然，这个 `if(+)` 的判断就不满足了，就会进入第一个 `else{}` 的范围内。然后就会执行 `else{ if-else }` 里面的 `if判断` ，再来判定是否是 `-` 号运算符。

判断 `-` 号运算符跟上也是同理，也是两种情况，满足与不满足。

条件满足就执行 `else{ if(-){} }` 范围内的 **减法** 相关代码，执行完成还是一样，代码直接跳出整个 `if-else` 。

记住，不是跳出 `else{ if-else }` 这个内层的 `if-else` ，而是最外层的，整体的这个 `if-else` 。

那如果用户此时输入的并不是 `-` 号运算符，那就继续执行 `else{ else{ if-else }}` 里面的这个 `if判断` ，就这么一层一层的套娃下去。

剩下的逻辑我就不给你梳理了，也就是说，加入了 `else` 这个规则之后，就可以在 `if判断` 正确的时候，无需执行剩下的那些判断了，代码会跳出整个 `if-else` 的范围。

从上面的表述来看，规则其实不麻烦，甚至也不是特别的绕，但是这种嵌套看的是真不舒服。

真要是一直这么嵌套下去，`else` 里面继续套 `if-else` ，在可以遇见的未来，我们可能要嵌套好多好多层。

毕竟科学计算器，可不只是有 `+ - * /` ，光两个数的计算法则就还有什么： `乘方（2 ^ 3 = 8）` 、 `求余（10 % 3 = 1）` 、 `最大公约数（gcd(12,8)=4）` 、 `最小公倍数（lcm(4,6)=12）` ...

所以，针对这样的条件判断，我们能否平行的写上几条判断路径，满足其中任何一个条件，也能直接跳出整个 `if判断` ，并且还不是这种嵌套的形式。

你知道我要说什么：

**有的，有的，兄弟有的！**


## if-else if

现在的逻辑很简单，我们只是想平行的写几条判断代码，判断的几个条件，有一个条件满足了，执行对应条件路径的代码，然后跳出整个判断。

在开始之前，稍微调整一下代码，原先是先定义 `bool类型` 的变量，接收字符串判等的值，再 `if` 判断这个 `bool类型` 的变量，这里稍微简写一下：

``` Csharp
...
//原先的写法
bool isPlus = operatorSymbol == "+";  // false;  //true;
if (isPlus)
{
}
 ↓
//现在的写法
if(operatorSymbol == "+")
{
}

...
```

现在就不做变量定义了， `if` 里面直接写上字符串判等表达式，这两种写法的作用是一致的。

接下来就需要介绍一种新的判断方式了：

原先是层层嵌套，不满足条件的走 `else` ，在 `else` 里面重新写一套 `if-else` ，再不满足就继续嵌套。

这里介绍判断的另一种写法，就是 `if-else if` ，直接上代码：

``` Csharp
...
//定义一个变量，用来接收用户输入的运算符号
MyConsole.WriteLine("请输入一个运算符号（+ - * /）！");
string operatorSymbol = MyConsole.ReadLine();

if (operatorSymbol == "+")
{
	//加法判断
	MyConsole.WriteLine("需要进行加法运算");
	int sum = 0;

	sum = num1 + num2;

	MyConsole.WriteLine(sum);
}
else if (operatorSymbol == "-")
{
	//减法判断
	MyConsole.WriteLine("需要进行减法运算");
	int difference = 0;

	difference = num1 - num2;

	MyConsole.WriteLine(difference);
}
else if (operatorSymbol == "*")
{
	//乘法判断
	MyConsole.WriteLine("需要进行乘法运算");
	int product = 0;

	product = num1 * num2;

	MyConsole.WriteLine(product);
}
else if (operatorSymbol == "/")
{
	//除法判断
	MyConsole.WriteLine("需要进行除法运算");
	int quotient = 0;

	quotient = num1 / num2;

	MyConsole.WriteLine(quotient);

}

MyConsole.WriteLine("计算已经完成");
...
```

针对当前这种情况，同一个变量的多分支路径判断，我们可以使用 `else if()` 的形式。

`if()` 写上第一个条件，紧接着 `else if()` 写上第二个条件，以此类推，有几个条件就可以写几个 `else if()` ，并且它们都是平行的，不需要像之前那样挨个嵌套。

执行逻辑也是非常简单，先看 `if()` 条件是否满足，如果满足则跳出整个 `if-else if` ，如果不满足就看第一个 `else if()` 条件是否满足，就这么挨个走下去。

真要是所有 `else if()` 的判断都不满足，那这一系列判断代码都不用执行了，正常走下面代码即可。

当然，你也可以增加一个保底路径，就是最后添加一个 `else` ，代码就变成了：

``` Csharp
...
else if (operatorSymbol == "/")
{
	//除法判断
	MyConsole.WriteLine("需要进行除法运算");
	int quotient = 0;

	quotient = num1 / num2;

	MyConsole.WriteLine(quotient);

}
else
{
	MyConsole.WriteLine("运算符输入有误，没有匹配到对应的计算方式");
}

MyConsole.WriteLine("计算已经完成");
...
```

这就是保底路径，表示如果上方 `if` 、 `else if` 都不满足的话，那就走这最后一个 `else` 。

需要注意一点的是：这里的 `else{ }` 并没有 `()` ，理解起来也不苦难，毕竟我是最后一种情况，并不需要写判断条件，哈哈哈。

> 判断一定是 `if()` 起手，后面可以接 `else if(){}` 或者 `else{}` ，当然也可以只写一个 `if()` ，前面咱们演示过了。但是千万不能凭空先出现 `else if()` 或者 `else{}` 。
