## 主动分支

从目前介绍的规则以及代码的书写角度来看，所有代码几乎都是要执行的。

毕竟代码从上至下依次运行，所以你写多少代码就执行多少代码，也是很符合逻辑的。

可是正如咱们的人生一样，哪有唯一的标准路径，每天都在充满变数，需要你时刻抉择自己前进的方向！

代码亦是如此，也需要进行分支、方向的抉择。

只是代码的方向可以控制、可以重来，人生虽不能重走，但也要落子无悔，你走的就是最好的方向！

**百川分流，各有所归。**

> 前面书写的 `try-catch` 也算是一种分支，但是这种分支非常的不可控，必须要报错了才能进入 `catch` 的分支。

**让我们来主动控制分支吧！**


## 输入运算符号

为了让程序支持不同的运算法则，其实就是让用户选择不同的运算符号。

只不过咱们没有界面让用户选择，暂时可以让用户直接输入运算规则。

这其实并不是什么难事，只需要添加一点代码，让用户直接输入运算符号 `+` 、 `-` 、 `*` 、 `/` 就行。

收集运算符号就写在收集两个计算数字之后：

``` Csharp
...
int num2 = 0;
try
{
	num2 = int.Parse(content2);
}
catch
{
	MyConsole.WriteLine("输入的并不是一个数字！");
}

//定义一个变量，用来接收用户输入的运算符号
MyConsole.WriteLine("请输入一个运算符号（+ - * /）！");
string operatorSymbol = MyConsole.ReadLine();

int sum = 0;

sum = num1 + num2;
...
```

可以看到，在收集完 `num2` 之后，紧接着提示了一个运算符号的信息，然后用变量 `operatorSymbol` 来记录用户的输入。

**希望你知道怎么输入加减乘除这四个运算符号。**

代码运行起来的效果也很不错：

![接收运算符号截图](images/8cd570ef-16ff-491f-95b6-a244fc64f67a.png)

重新定义了一个变量 `operatorSymbol` ，专门用来接收需要的运算符号。

只是现在你输入任何的运算符号都是没有意义的。

毕竟咱们只是定义这个变量接收用户的输入而已，暂时还没有用这个变量的值做任何事情。


## if判断

之前得到用户输入的字符，我们调用 `int类型` 下面的 `parse()` 方法，来将一个字符串，转换成数字。

现在我们得到用户输入的运算符字符串，但是并没有这样一个 `运算符类型` 下面的 `parse()` 方法，给我们调用，把输入的字符串转换成代码中的运算符。

这里就能用上分支代码了，既然你不知道字符串怎么转换成代码中的运算符号，那我干脆多写几句代码。

一次性把输入两个数的 `加法` 、 `减法` 、 `乘法` 、 `除法` 这些代码都写了。

这样如果用户输入了 `+` 号字符串，我就执行 `加法` 相关的代码，用户输入了 `-` 号字符串，我就执行 `减法` 相关的代码，其它亦是如此。

那就需要对用户的输入进行一个判断，判断输入的内容是不是特定的字符，也就是说用户是不是输入的 `+ - * /` 这四个字符中的一个。

### if语法

在上述的内容中，我们需要知道输入的内容是否等于 `+ - * /` 这四个运算符号中的一个，这里我们可以使用 **字符串判等** 。

在介绍两个字符串是否相等之前，需要接触一个新的变量类型 `bool` 。

因为这跟 `if` 的语法息息相关， `if` 的语法非常简单，就是条件配合着范围。

先来看一下语法示例代码：

``` Csharp
...
if (bool类型的值)
{ 
	
}
...
```

`bool类型` 的值也是非常简单，只有 `true` 和 `false` 两种状态。

**映射到代码上就是：**

``` Csharp
...
if (true)
{ 
	// 此范围代码执行
}

if(false)
{
	// 此范围代码不执行
}
...
```

**映射到逻辑上就是：**

``` Csharp
...
if (条件成立)
{ 
	// 此范围代码执行
}

if(条件不成立)
{
	// 此范围代码不执行
}
...
```

`if` 也是我们编程思维构建的关键节点，很多人在初期都会面临下述的情况：

**明明已经理清思路，描述清楚流程了，但是代码写不出来，或者说无法将思路转换为代码！**

一方面是因为咱们接触的少了，还没有形成固定思维。

更重要的另一方面，则是因为你一直在思考如何打通虚拟与现实这条路径，而忽略了虚拟就应该是虚拟的，现实就应该是现实的。

**任何现实的想法，其实都应该在虚拟中拷贝一份。**

下面用两种情况来描述一下这种思维的转变。


### 固定条件

先用最简单的方式来演示 `if` 到底是怎么玩的。

还是接着前面已经写好的代码：

``` Csharp
...
//定义一个变量，用来接收用户输入的运算符号
MyConsole.WriteLine("请输入一个运算符号（+ - * /）！");
string operatorSymbol = MyConsole.ReadLine();

bool isPlus = true;
if (isPlus)
{
	MyConsole.WriteLine("需要进行加法运算");
}

int sum = 0;

sum = num1 + num2;
...
```

定义 `operatorSymbol` 变量记录用户输入的运算符之后，咱们定义了一个 `bool类型` 的变量 `isPlus` ，初始值给的 `true` 。

这里的 `if(isPlus)` 就相当于 `if(true)` ，表示条件成立， `if(){}` 范围内的代码正常执行，输出信息： **"需要进行加法运算"** 。

![演示bool为true截图](images/9ba00aab-5d9f-4f6a-b0d7-3aa06d3e7ae4.png)

> 其实可以直接写 `if(true)`  ，这里多走一步，看的更清晰一点。

下面我们把 `isPlus` 的初始值调整成 `false` ，表明条件不满足，则不会执行 `if(){}` 范围内的代码，也就看不到任何信息输出。

``` Csharp
...
bool isPlus = false;  //true;
if (isPlus)
{
	MyConsole.WriteLine("需要进行加法运算");
}
...
```

![演示bool为false截图](images/0a1e976a-60d7-4402-90cf-95addeb7c674.png)

这么看来 `if` 的用法是真的简单，只是这样的实际意义大小了，大部分情况下代码并不是这种写死的状况，是需要跟着我的需求，我的条件来调整的。

这也就是为什么语法看起来不难，可真正应用起来的时候，会发现根本无从下手。


### 字符串判等

此时我们并不需要了解 `if` 的这种固定用法，而是要根据我们当前的情况来指定条件。

需求现在已经是明确的了，条件也已经非常清晰，判断相等即可。

判断谁和谁相等是需要我们考虑的，这就是需要获取的参数，一个是用户输入的运算符号，一个是 `+ - * /` 中固定的字符串。

构造的条件就是：输入的字符串是否等于 `+ - * /` 中的某个字符，如果等于就是 `true` ，否则就是 `false` 。

**那如何如何通过代码来判断两个值是否相等呢？**

在 `C#` 中，直接使用 **两个连续等于号** 即可。

`==` 表达式是用来判断左右两个值是否相等，返回 `bool类型` 的值，如果相等返回 `true` ，否则返回 `false` ，最后的结果我们可以存放在 `bool类型` 的变量中。

所以现在就是左右两个值，一个值就是我们输入的运算符号，目前记录在 `string类型` 的变量 `operatorSymbol` 中，一个就是 `+ - * /` 这四个固定的运算符号中的一个。

暂时我们先判断一个 `+` 号运算符，那代码就变成了：

``` Csharp
...
//定义一个变量，用来接收用户输入的运算符号
MyConsole.WriteLine("请输入一个运算符号（+ - * /）！");
string operatorSymbol = MyConsole.ReadLine();

bool isPlus = operatorSymbol == "+";  // false;  //true;
if (isPlus)
{
	MyConsole.WriteLine("需要进行加法运算");
}
...
```

> `==` 两边的类型要一致，这没什么好说的，一贯如此。 `operatorSymbol` 是 `string类型` ， `"+"` 也是 `string类型` 。

下面测试的时候，依次进行 `+` 号字符的输入，和 `非+` 号字符的输入了。

![演示非+号字符输入截图](images/7b2e1d9e-e627-4131-8632-a33fe5a67b39.png)

### 完善加法分支判断

下面就是把原先的 **加法计算** 放到 `if` 的范围内。

``` Csharp
...
//定义一个变量，用来接收用户输入的运算符号
MyConsole.WriteLine("请输入一个运算符号（+ - * /）！");
string operatorSymbol = MyConsole.ReadLine();

bool isPlus = operatorSymbol == "+";  // false;  //true;
if (isPlus)
{
	MyConsole.WriteLine("需要进行加法运算");
	int sum = 0;

	sum = num1 + num2;

	MyConsole.WriteLine(sum);
}

MyConsole.WriteLine("计算已经完成");

MyConsole.ReadKey();
...
```

可以看到，只有满足 `if条件` ，在提示输入运算符号的时候，只有输入 `+` 才计算两个数字相加，并进行结果的输出。

为了直观感受代码是否走了 `if` 判断，特意加了一句最终的信息输出： **计算已经完成** 。

此时当你正确输入 `+` 号字符的时候，可以看到 **需要进行加法运算** 的信息输出，并且看到正常的计算结果，还有 **计算已完成** 的信息输出：

![完善if加法计算截图](images/cacab4da-caa5-4d31-8f95-5dbbad191cda.png)

如果不是正确输入 `+` 号字符，就只能看到 **计算已完成** 的信息输出：

![演示非+号字符输出截图](images/7b2e1d9e-e627-4131-8632-a33fe5a67b39.png)

这也提示我们并没有满足 `if` 的条件，所以响应的代码并不执行。

> 目前我们写代码还是比较狼狈的，代码走了哪个分支，具体怎么走的，都是一种黑盒，看不到具体的执行流程，只能依靠这种打印信息的方式，来推测代码的路径。
> 很快会介绍 **调试** ，这样就能知道代码具体的执行过程了。

上述的内容，咱们不仅仅是在完善 `加法计算` ，介绍 `if` 、 `==` 这样的语法，更重要的是想将你拉到虚拟世界中去。

**你在现实中构建的思维，在虚拟的软件环境中都是不存在的，需要你主动的去构造出需要的所有内容和参数。**

代码只是现实的 **映射/拷贝** 、你脑海中的场景和过程，在代码中都需要有内容和它一一对应上。

从这样一个小小的案例中，希望传达给你的意思是，要把想法转到成代码，一切都需要去构造。需要什么就要去构造什么，缺什么就准备什么，想法要拆分到足够小、足够细，一步一步的指挥代码去完成这件事。

**现实跟虚拟没有任何关系，但是我们想用虚拟去无限逼近现实！**
